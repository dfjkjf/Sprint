
目标：机器人方向的中间件性能优化岗。8 周产出一个可运行的通信性能实验项目，作为面试主案例。

一面考「会不会」，主管面考「能不能扛」，HR 面考「留不留得住」。三轮问的是三件不同的事，所以材料分开准备；共用的知识只在最强归属处写一次，其余轮次用链接索引，不重复。

## 一、三轮怎么过

| 轮次 | 面试官 | 考什么 | 判定方式 | 材料 |
| --- | --- | --- | --- | --- |
| 一面 | 工程师、组长 | 会不会：原理、证据、工具 | 顺着简历往下钻，追问三层不变形 | [first-round-interview](first-round-interview/README.md) |
| 主管面 | 平台负责人、技术经理 | 能不能扛：架构判断、资源组织、对外承诺 | 给一个局面要方案，场景题作答 | [tech-lead-interview](tech-lead-interview/README.md) |
| 总裁面 | 业务负责人、VP | 值不值得投资：行业判断、稳定性、成长性 | 主观判断，一票否决 | [executive-interview](executive-interview/README.md) |
| HR 面 | HRBP | 留不留得住：动机、薪资、稳定性 | 不谈技术，只谈风险 | [hr-interview](hr-interview/README.md) |

总裁面通常与主管面同一场进行、由更高层接续，考点完全不同，因此单独备料。

## 二、8 周安排

| 周次 | 内容 | 主要服务 |
| --- | --- | --- |
| Week1 | C++ 对象、并发、内存、架构与排查 | 一面 |
| Week2 | 进程与虚拟内存、ROS 2 运行时 | 一面 |
| Week3 | 网络协议与 DDS：RTPS、发现、QoS | 一面 |
| Week4 | 通信组件架构设计 | 主管面 |
| Week5 | 共享内存与零拷贝 | 一面深挖 |
| Week6 | 性能分析与实时性 | 一面、主管面 |
| Week7 | 综合实验与项目陈述 | 主管面、总裁面 |
| Week8 | 多轮模拟与话术定稿 | 三轮 |

两条边界，用来避免重复：

- **Week5 只讲共享内存与零拷贝**——loan 机制、跨进程所有权、序列化成本、收益边界。内存池、对齐、memcpy、Benchmark 方法已在 Week1 Day3 讲透，不再回头。
- **ROS 2 运行时归 Week2**——Executor 与回调组本质是线程模型问题，与并发同源；Week6 只讲它的调度延迟与尾延迟测量，不重讲模型。

## 三、每周节奏

| Day | 内容 | 时长 |
| --- | --- | --- |
| Day 1 | 原理理解：画出调用链、数据流、线程关系 | 2h |
| Day 2 | 架构设计：先自己定接口与约束，再让 AI 评审 | 2h |
| Day 3 | 实现：给明确设计，让 AI 写代码、测试、构建脚本 | 2–3h |
| Day 4 | 审查与实验：查关键路径，跑实验，核对数据是否支持结论 | 2–3h |
| Day 5 | 面试表达：口头作答、接追问、整理话术 | 2h |

每周 10–12 小时，8 周总计约 80–96 小时。

每周留下四份成果：原理图（能讲清机制）、设计文档（说清为什么这样设计）、实验报告（用数据证明判断）、面试话术（做过什么、解决了什么、效果如何）。四份都留不下的那一周，等于没有推进。

## 四、分工

| 工作 | 你负责 | AI 负责 |
| --- | --- | --- |
| 需求分析 | 定义问题和目标 | 补充遗漏 |
| 原理学习 | 理解机制、判断对错 | 讲解、举例、源码导读 |
| 架构设计 | 决定模块边界与接口 | 提供备选方案与评审 |
| 代码实现 | 给出设计约束 | 编写大部分代码 |
| 测试 | 确定目标与验收标准 | 编写测试与运行脚本 |
| 性能分析 | 判断瓶颈与因果关系 | 采集数据、提出假设 |
| 技术决策 | 最终决策 | 分析优缺点与风险 |
| 面试表达 | 讲出自己的判断 | 模拟面试、打磨表达 |

代码实现可以大量外包，技术判断不能外包。AI 能写出一个可编译的线程池，但不能替你证明它比原实现更快。

同时要维护一份经历台账，明确每条简历内容的性质，避免把「仅理解原理」说成「实际做过」：

| 项目内容 | 记录要求 |
| --- | --- |
| 已实际做过 | 有代码、日志、实验或工单可查 |
| 已独立设计 | 有设计方案，但不一定落地 |
| AI 辅助完成 | 明确自己负责的设计与验收部分 |
| 仅理解原理 | 可以回答原理，不包装成实践经历 |

## 五、验收标准

不看学完了多少知识点，看五件事：

- 能画出 ROS 2 → RMW → DDS → RTPS/Transport 的完整链路，并解释关键机制
- 能独立设计一个异步通信组件，说清线程模型、对象生命周期、资源所有权
- 能解释零拷贝、内存池、预分配的机制、适用场景与代价
- 面对 CPU 高、延迟高、抖动大，能提出假设、设计实验、定位到根因
- 能在 3 分钟内介绍一个真实项目，并经受 15 分钟以上追问

## 六、时间分配

- 20%：C++、操作系统、网络基础
- 25%：通信机制与架构设计
- 35%：零拷贝、性能分析与优化
- 20%：面试表达与综合答辩

已有 DDS 中间件经验，不需要重学一遍 DDS；真正要补的是 C++ 内存模型、Linux 调度、ROS 2 执行机制和系统级性能优化。
